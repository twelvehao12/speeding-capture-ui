# 2K 预览与快速操作优化实施记录

环境：Windows、Qt 6.11.1、MinGW 13.1，板端协议和主辅码流固定分辨率保持原有约定。

## 已实施

| 链路 | 改动 |
| --- | --- |
| RTSP 显示 | 默认 `QMediaPlayer → QVideoWidget`，正常预览不再逐帧 `toImage()`；保留软件绘制后端供同机对比。停止操作幂等，后端过滤失效播放代次。 |
| 开流调度 | 设备、URL、码流角色共同去重；快速选择合并 200 ms；停止立即取消待开流；配置应用后的强制重开独立保留。 |
| 检测线配置 | 每次设备绑定使用独立上下文、代次和 `QPointer`；两个读取请求都结束后才解除加载；切设备取消延迟刷新，旧保存回调不能继续操作新设备。 |
| SQLite | 专用线程创建、使用和关闭连接，串行执行事务和查询；完成回调回到上下文线程；取消尚未开始的任务并屏蔽失效结果；增加匹配事件排序的索引。 |
| 图片回看 | 100 ms 合并选择，两个解码工作线程，每个面板最多一个执行中任务；按窗口尺寸和 DPI 解码；共享 64 MiB LRU，键包含路径、文件大小、修改时间和目标尺寸；旧结果不能覆盖新选择。双击可用图片由系统查看器打开原图。 |
| 清空及导出 | 每页 100 条，清空通过异步续调推进；CSV 在工作线程逐页写入 `QSaveFile`，不再累积全部记录；提供进度和取消，图片删除失败仍保留事件。 |
| 下载与 FTP | HTTP 网络读取和文件写入放在 I/O 线程，64 KiB 分块、256 KiB 接收缓冲；保留类型、长度和 JPEG 格式验证；FTP 收取和写盘在独立线程，界面异步启动。 |
| 缓存维护 | 扫描、排序和删除在后台，循环检查取消标志；使用文件占用保护跳过正在显示或下载的文件；关闭及切换目录可取消维护。 |
| 生命周期及界面 | HTTP 完成/取消/上下文销毁均清理连接、计时器和 reply；下载代次及临时文件互相隔离；列表淘汰同步清理图片状态；实时记录按 100 ms 合并更新，分辨率只在变化时更新，时间和 ID 列不再反复自动测宽。 |

下载保留全局最多 4 个、每设备 1 个；等待队列及查询/重试槽位以 256 为目标上限，另有最多 4 个执行中任务。溢出请求保存为数据库 Queued 状态，内存调度器不保留完整事件或状态通知条目。Queued/Downloading/RetryWait 条目在有空位时分批补入，恢复查询只针对当前允许下载的设备；数据库线程中的待提交写入另计入 pending_requests。显式取消保存为 Failed/cancelled，后台补队列不会使其复活；重新 enqueue 可以重新请求。

取消不撤销已经完成的文件删除或数据库提交。导出使用临时文件，取消未提交的导出保留原目标文件。维护与显示之间的文件保护只协调本进程；系统原图查看器拥有独立生命周期。

## 构建与自动验证

本次 Release 构建使用独立目录 `build/performance-release`，未替换已有发布目录。生成的程序为 `CameraManagerApp.exe`，验证工具为 `Rv1126bRtspSpike.exe`。在已配置 Qt 环境的机器运行；交付其他机器前仍需沿用项目打包流程部署 Qt DLL 和插件。

验证记录：Debug、Release 均编译成功；Release 沙箱内 28 组测试全部通过，全量运行耗时 76.60 秒，结果保存在 `build/performance-release/release-results.xml`。Windows 凭据测试另用 Debug 构建在沙箱外通过。

最后补充 FTP 被动端口释放修复后，重新构建两种配置，并复跑 Release 的 FTP、设备操作界面和应用运行时 3 组相关测试，全部通过；记录为 `build/performance-release/ftp-final-results.xml`。

```powershell
cmake -S . -B build/performance-release -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH=C:/Qt/6.11.1/mingw_64 -DCMAKE_MAKE_PROGRAM=C:/Qt/Tools/Ninja/ninja.exe -DCMAKE_CXX_COMPILER=C:/Qt/Tools/mingw1310_64/bin/g++.exe
cmake --build build/performance-release --parallel 4
$env:PATH = 'C:/Qt/6.11.1/mingw_64/bin;C:/Qt/Tools/mingw1310_64/bin;' + $env:PATH
ctest --test-dir build/performance-release --output-on-failure --timeout 120
```

新增回归覆盖以下边界：

- 连续 1000 次角色切换和重复 Online 通知，只打开最终目标；停止后定时器不复活播放。
- 检测模式/线位请求乱序返回、切设备后旧保存返回、窗口销毁后的迟到回调。
- 真实 SQLite 写入 10 万条记录、尾页查询、主线程心跳仍运行、请求取消和上下文销毁、回调线程正确。
- 10 万条分页 CSV 导出及清空调度。此项使用生成记录的仓储替身验证分页、取消、栈深度和界面事件处理；不代表已实测 10 万张真实图片的磁盘删除速度。
- 1000 次图片选择保留最终图片，旧身份的图片状态不能覆盖；列表淘汰与持久选中索引。
- 图片取消后立即重试，旧下载完成不能结束新下载；300 条下载请求溢出后仍可从数据库恢复。
- 100 次 HTTP 请求后调用方连接及 reply 回落；取消、销毁上下文后重试；后台维护跳过占用文件及取消；性能日志后台落盘。
- FTP 控制连接在 STOR 后、数据连接前断开，临时被动监听器随会话释放；FTP 写入期间也使用文件占用保护。

Windows 凭据测试需要可写的 Windows 凭据管理器。受限沙箱内该测试会失败，已单独在沙箱外验证 Debug 测试通过；这不是程序回归失败。

## 实机诊断开关

正常使用不必开启日志。需要采样时，在启动程序前设置：

```powershell
$env:CAMERA_PERF_LOG = "$PWD/build/ui-performance.csv"
& ./build/performance-release/CameraManagerApp.exe
```

每 50 ms 采样主线程心跳，每 5 秒汇总一次，文件在独立线程写入；最多一个待写采样。超过 16 MiB 轮换为 `.previous`，只保留上一份。重启会覆盖指定日志，请每次对比使用不同文件名。

| CSV 字段 | 含义 |
| --- | --- |
| `heartbeat_p95_ms` / `heartbeat_max_ms` | 本窗口内心跳比 50 ms 计划间隔额外延迟的 P95 / 最大值，不是视频端到端延迟。 |
| `qobjects` | 当前应用对象树和顶层窗口树的去重对象数；不含无父对象的后台线程内部对象，不是进程全部分配对象。 |
| `pending_requests` / `queued_downloads` / `active_downloads` | API/数据库未完成请求、内存等待下载/查询槽位、执行中下载计数。 |
| `evidence_states` | 当前列表保留的图片状态数。 |
| `received_frames` | 当前后端收到的有效帧累计数，不能解释为屏幕实际显示帧数。 |
| `software_paints` | 软件回退窗口的绘制次数。默认原生窗口不提供实际呈现计数。 |
| `play_max_ms` / `stop_max_ms` | 后端同步 play/stop 调用的累计最大耗时，不等于首帧耗时。 |

原生显示与软件回退对比：

```powershell
$env:CAMERA_PREVIEW_RENDERER = 'software'
$env:CAMERA_PERF_LOG = "$PWD/build/ui-software.csv"
& ./build/performance-release/CameraManagerApp.exe
Remove-Item Env:CAMERA_PREVIEW_RENDERER
```

`software` 仅切换显示路径，不强制软件解码。单独比较解码后端时，可使用 Qt 官方的配置：

```powershell
$env:QT_FFMPEG_DEBUG = '1'
$env:QT_LOGGING_RULES = '*.multimedia.*=true'
$env:QT_FFMPEG_DECODING_HW_DEVICE_TYPES = ',' # 禁用硬解后端
```

恢复硬解偏好用 `d3d11va,dxva2`，重启程序后生效。实际选择必须以 Qt/FFmpeg 运行日志和 GPU 解码引擎占用确认。上述环境变量属于 Qt 私有配置，升级 Qt 后应重新核对。[Qt FFmpeg 配置文档](https://doc.qt.io/qt-6/advanced-ffmpeg-configuration.html)

原有验证工具继续记录首帧、CPU、工作集、停止耗时及人工端到端延迟样本；新加收到帧的间隔 P95/最大值及渲染路径。示例中的地址需要替换为测试设备：

```powershell
$env:CAMERA_PERF_LOG = "$PWD/build/rtsp-heartbeat.csv"
& ./build/performance-release/Rv1126bRtspSpike.exe --main-url rtsp://192.168.1.10/live/0 --sub-url rtsp://192.168.1.10/live/1 --duration-minutes 30 --output ./build/rtsp-native.csv
```

## 待实机验收

自动测试通过不等于已确认客户卡死根因，也不代表已测得性能提升比例。尚需在客户显卡、驱动和设备网络环境下完成：

1. 主码流 2560×1440，H.264/H.265 各 30 分钟；统一 Release、源帧率、显示尺寸和测试片段，同机比较原生与软件回退、硬解与软解。
2. 每秒 5～10 次切设备/切流、累计 1000 次；开流时停止、重连时切换、断网后关闭。记录最长 stop 耗时；如果永久无响应，保留挂起时线程堆栈。
3. 检测线透明叠加、鼠标拖动、全屏/缩放、100%/150%/200% DPI 下的对齐与交互。
4. 快速点选抓拍时最后选择正确，心跳额外延迟 P95 目标低于 100 ms；原图查看按需启动。
5. 真实 10 万条数据库配合图片的查询、导出、清空和取消；用进程内存曲线确认导出不随记录总数线性增长。
6. 连续运行 8 小时，观察请求、下载、图片状态、工作集和对象计数能否回落；GPU 占用通过任务管理器或图形诊断工具记录，当前 CSV 不自动采集 GPU。
